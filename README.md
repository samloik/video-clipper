# video-clipper

Вырезает фрагменты видео по таймкодам из YouTube, TikTok, VK, Rutube, Instagram и любого
другого сайта, который умеет [yt-dlp](https://github.com/yt-dlp/yt-dlp), а также из локальных
файлов. Есть CLI и минимальный локальный веб-интерфейс.

## Установка

```bash
cd ~/programs/video-clipper
uv venv --python 3.14 .venv
uv pip install --python .venv/bin/python -e ".[dev]"
cp config.example.json config.json    # поправь пути под себя
```

Нужен `ffmpeg` в PATH (`sudo apt install ffmpeg`). Поддерживается ffmpeg 4.x — синтаксис
5+/6+ (`-fps_mode` и подобные) не используется.

## Быстрый старт

```bash
# YouTube: один фрагмент
video-clipper "https://youtu.be/ID" --range 1:12-1:45

# TikTok: скачать и вырезать (прокси и cookies — из config.json)
video-clipper "https://www.tiktok.com/@user/video/123" --range 0:05-0:20

# локальный файл, несколько фрагментов
video-clipper ~/Videos/lecture.mp4 --range 0:10-0:25 --range 12:00-12:30

# список отрезков из CSV: start,end,name
video-clipper "https://youtu.be/ID" --csv clips.csv

# быстрый режим: без перекодирования, точность до ключевого кадра
video-clipper video.mp4 --range 1:00-1:20 --fast

# только посмотреть, что будет нарезано (URL не скачивается)
video-clipper "https://youtu.be/ID" --range 0:10-0:20 --dry-run

# весь ролик целиком — без таймкодов (копия потока, без перекодирования)
video-clipper "https://youtu.be/ID"

# вертикально 9:16 для смартфона (центр-кроп 1080x1920)
video-clipper video.mp4 --range 0:10-0:25 --vertical

# вертикально с размытым фоном вместо обрезки
video-clipper "https://youtu.be/ID" --range 1:00-1:20 --blur

# веб-GUI на 127.0.0.1:8765
video-clipper-gui
# или
video-clipper --gui
```

Таймкоды: части разделяются любым из `:` `,` `.` `/` `\`.

- одна часть — секунды: `45` → 0:00:45;
- две — минуты:секунды: `34:43` → 0:34:43, `1:12` = `1.12` = `1/12` = `1\12` → 0:01:12;
- три — часы:минуты:секунды: `1:02:03`;
- крайнюю часть можно опустить: `:12` → 0:00:12 (но `:45` — это 45 с, а не 3:45);
- три цифры после точки/запятой — миллисекунды: `1:12.500` → 72.5 с.

Отрезок: `НАЧАЛО-КОНЕЦ` (`0:10-0:20`) или `НАЧАЛО=ДЛИТЕЛЬНОСТЬ` (`1:00=0:30` → 1:00–1:30).
Несколько отрезков в одном `--range` — через `;`: `--range "0:10-0:20; 2:00=45"`.

Диапазон проверяется по реальной длительности ролика **до** скачивания: конец за
пределами видео, например `0:00-99:00` на пятнадцатиминутном ролике, даёт отказ
за секунды вместо многоминутной загрузки, которая всё равно не даст клипа.

Имя файла по умолчанию — `<slug>__<начало>__<конец>.mp4`; переопределяется `--name`
(только один отрезок) или третьей колонкой CSV.

## Режимы

| режим | флаг | точность | скорость |
|---|---|---|---|
| точный (по умолчанию) | `--accurate` | кадровая | перекодирование H.264/AAC |
| быстрый | `--fast` | до ключевого кадра | без перекодирования (`-c copy`) |
| вертикальный | `--vertical` | кадровая | 9:16 центр-кроп 1080x1920 |
| вертикальный с фоном | `--blur` | кадровая | 9:16, кадр целиком на размытом фоне |

В быстром режиме границы могут сместиться к ближайшему ключевому кадру — на коротких клипах
это заметно, поэтому по умолчанию включён точный режим.

## Веб-интерфейс

`video-clipper-gui` поднимает сервер на адресе из `gui_host` (по умолчанию `127.0.0.1`,
порт 8766) и открывает браузер. На странице: зона drag & drop (файл загружается в `cache/`),
поле ссылки, два поля таймкода, галочка быстрого режима, кнопка «Нарезать», список готовых
файлов со ссылками. Нарезка идёт в фоне, ошибки показываются в интерфейсе. Внешних JS и CDN нет.

Вертикальный режим в GUI имеет два варианта фона: `обрезать бока` (crop) и
`размытый фон` (blur) — тот же выбор, что у бота словами «вертикально» и «фон».

Доступ из локальной сети: поставь `gui_host: "0.0.0.0"` и укажи `gui_password_file` — файл
с паролем (права `600`). Без пароля сервер на не-loopback адресе **не запустится**: GUI отдаёт
файлы и умеет резать, оставлять его открытым в сети нельзя. Сессия — подписанная HttpOnly
cookie на 12 часов, либо на 30 дней с галочкой «запомнить меня» (подпись cookie лежит в
`gui_secret_file`, поэтому сессия переживает перезапуск сервиса); после 6 неверных паролей
с одного IP вход блокируется на 10 минут. Пароль можно задать и переменной
`VIDEO_CLIPPER_GUI_PASSWORD`.

## Конфигурация

`config.json` (см. `config.example.json`), значения перекрываются флагами CLI:

- `output_dir` — куда складывать фрагменты (`./output`)
- `cache_dir` — куда скачивать исходники (`./cache`, удаляются после нарезки)
- `default_resolution` — максимальная высота при скачивании (720)
- `cookies` — путь к `cookies.txt` для yt-dlp (не хранится в git)
- `proxy` — например `socks5://127.0.0.1:10808`
- `ffmpeg_path`, `ffprobe_path`, `keep_source`, `gui_host`, `gui_port`, `gui_password_file`,
  `log_file`
- `use_sections` — скачивать только нужные участки через `download_ranges` (по умолчанию
  `false`: на части сайтов такой режим зависает, поэтому он экспериментальный; при `true`
  срабатывает, когда отрезки покрывают ≤40% видео)

## Telegram-бот

Основной канал общения: присылаешь ссылку и таймкоды — бот отвечает готовыми роликами.
Можно и файлом: видео вложением до 20 МБ (лимит Bot API на скачивание), таймкоды — в подписи
(`0:10-0:20`, `вертикально 0:05=15`). Файлы крупнее бот скачать не может — он подскажет
ссылку на веб-интерфейс, где лимит 4 ГБ.

```bash
# 1. токен от @BotFather положи в файл (в чат его присылать не нужно)
printf '%s' '123456:ABC...' > ~/.hermes/video-clipper-bot.token
chmod 600 ~/.hermes/video-clipper-bot.token

# 2. свой chat_id узнаешь у бота командой /id, впиши в config.json:
#    "telegram_chat_ids": [370180073]

# 3. запуск
systemctl --user daemon-reload
systemctl --user enable --now video-clipper-bot
journalctl --user -u video-clipper-bot -f
```

Формат сообщений:

```
https://vm.tiktok.com/ZSpFs5jXJ/ 0:10-0:20
https://youtu.be/ID 0:05 0:12 fast
<ссылка>
0:10-0:20
0:30-0:40
```

Команды:

- `/id` — chat_id, `/status` — что лежит на машине, когда каждый файл удалится, и возраст cookies,
  `/time 1:30` — сколько хранить файлы (30 — минут, `1:30` — час тридцать, `2ч` — два часа),
  `/help` — памятка;
- `/stop` — прервать текущую нарезку: ffmpeg убивается, загрузка обрывается на ближайшем шаге;
- `/resume` — повторить последний запрос (ссылку, таймкоды и режим бот помнит);
- `/new` — начать с чистого листа: забыть последний запрос, очистить задания и удалить файлы;
- `/clean` — только удалить файлы, состояние запроса не трогает.

Клип больше 45 МБ бот не пережимает, а режет по ключевым кадрам на части
(`clip_part1.mp4`, `clip_part2.mp4` …) и присылает их с подписью «часть i/n» —
качество остаётся исходным. Пересжатие включается только если резать нечем
(в клипе нет ключевых кадров) или если в конфиге `telegram_policy: "compress"`.

Если YouTube отвечает «confirm you're not a bot», бот не сдаётся: пробует другие
клиенты (`android`, `tv_embedded`, `web`), а после полного отказа уходит в паузу на
12 минут и повторяет тот же запрос сам через 15 — снять повтор можно `/stop`.

Таймкоды терпимы к опечаткам края: `0:00-:30` читается как `0:00-0:30`, `1:` — как `1:00`.
Дыра в середине (`1::30`) по-прежнему ошибка — это опечатка, а не сокращение.

Режим без перекодирования доступен двумя способами: словом `fast`/`быстро` в сообщении или
кнопкой **«⚡ Без перекодирования (быстро)»** под готовым роликом — она перерезает тот же
отрезок через `-c copy` из уже скачанного файла, без повторной загрузки (секунды вместо минут).
Кнопка живёт `retention_minutes`; если исходник уже удалён, бот попросит прислать ссылку заново.

Ссылка без таймкодов = весь ролик целиком: файл remux-ится без перекодирования
(`<slug>__full.mp4`), а если он больше лимита Telegram (50 МБ), бот сам сжимает до 45 МБ
(720p → 480p, с пометкой в подписи).

Вертикальные варианты — кнопками **«📱 Вертикально 9:16»** и **«📱 Вертикально + размытый фон»**
под роликом, либо словом в запросе: `вертикально`, `vertical`, `9:16`, `шортс`, `reels`,
для размытого фона — `размытый фон` / `blur`. Вертикальный режим всегда перекодирует
(кроп нельзя отдать копией потока), файлы получают суффикс `_vertical` / `_vertical_blur`.

## Хранение файлов

- Срок хранения по умолчанию `retention_minutes` = 30 мин; его меняют `/time` у бота и кнопка
  «Хранение» в GUI. Значение хранится рядом с конфигом в `retention.txt` и переживает перезапуск.
- Оригинал живёт выбранный срок с момента последнего использования —
  повторная нарезка той же ссылки идёт из кеша, без скачивания.
- Клипы — столько же; после отправки в Telegram копия в чате остаётся, на машине чистится.
- Чистка запускается при каждом запросе и раз в минуту в боте; вручную — `/clean`
  или `video-clipper ... ` (CLI чистит только `cache/`).

## Отчёт

`--json-report report.json` пишет по каждой нарезке: путь, начало, конец, фактическую
длительность, режим и размер, плюс итоги по прогону.

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

Тесты не ходят в сеть: yt-dlp мокается, видео для интеграционных тестов генерируется
локально через `ffmpeg -f lavfi -i testsrc`.

## Ограничения

- Длительность в контейнере может быть на 1–2 кадра больше заказанной из-за гранулярности
  AAC-кадров; видеоточная длительность точная.
- Нет встроенной поддержки субтитров и вертикального кропа — отложено (см. план в Plan Manager).
- Сервер GUI: на localhost можно без пароля, на любом другом адресе пароль обязателен.
